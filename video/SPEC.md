# MOSAIC — 60 s product demo · design spec

Made with the [video-shotcraft](https://github.com/Vincentwei1021/video-shotcraft) pipeline in
**autonomous free-creation** mode: the agent chose direction, shots and storyboard and recorded
the reasoning here instead of stopping for sign-off at each stage.

## 0 · Product brief

| | |
|---|---|
| Product | MOSAIC Campaign Console — four agents (Segmentation, Creative Director, Composer, Guardian) turn one customer CSV into a separate email per micro-segment; a person approves and sends. |
| Audience | NUS-ISS SWE5008 assessors, peers, anyone opening the README. They need to see what the product *does*, in the order it does it. |
| Core claim | One generic email → one email per segment, with a human at the gate. |
| Must show | Company Info / CSV · 6 segments with explained traits and the age-proxy flag · per-segment creative direction · real editable email blocks · 10 Guardian checks with a REVISE · human Send · ledger · eval scorecard. |
| Format | 1920×1080, 30 fps, exactly 60.0 s (1800 f), English. |
| Audio | User-chosen BGM `Forward Motion.mp3` (hard constraint), SFX from the shotcraft library. Two renders: with and without BGM. |
| Data | The FatCatPillow demo workspace — 1,000 synthetic contacts and the run already shown in `docs/media/console/`. No real customer data. |

### Requirement → execution

| Requirement | Decision |
|---|---|
| "Real screenshots of the app" | Supabase project and Railway deploy are both down, so the real Console (`frontend/`, vite dev) is driven by Playwright with every API call answered from `capture/fixture/*.json`. The fixture is generated by `capture/build_fixture.py` with the backend's own code: `email_composer._build_blocks` assembles the email blocks, `guardian.run_checks` grades them, `csv_ingest` profiles the CSV, `eval.rubric` supplies the rubric. The rendered Guardian detail strings match the original run's screenshots word for word. |
| "Extremely high quality" | All page textures at 2× (email cut-outs and eval at 3×). 3D camera uses CSS `zoom` layout scaling (Q2). |
| "Forward motion" / 60 s | 100 BPM, beat = 18 f exactly; the film is beats 8–108 of the track (5.083 s → 65.083 s), so every cut is an integer beat. |
| "High motion graphics" | 2.5D camera on every UI shot, one hero technique per shot, three camera-level slams on the strongest hits only (R4). |

## 1 · Visual direction

Chosen: **"Glass studio"** — the Console's own lavender gradient-mesh ground and white glass cards,
Inter + JetBrains Mono, indigo `#4F46E5` as the single UI accent, and the eight MOSAIC tile colours
reserved for brand moments (colourise, mark, outro dust). Rejected: a dark "launch event" skin
(fights the product's light glass look) and a paper/editorial skin (wrong register for an AI console).

Motion personality (preset *Professional/B2B* nudged toward *Bold* for the drop):
entrances ~18–21 f on `bezier(0.16,1,0.3,1)`, landings that should bounce use `y1>1`
(`bezier(0.34,1.45,0.64,1)`), camera moves on `bezier(0.33,0,0.15,1)`, holds ≥30 f on brand
marks. Captions: a frosted glass plate, mono kicker 32 px indigo, Inter 700 headline 76 px,
36 px sub (Q11 floors). Styleframe skipped: the product's own design system is the brand spec
(tokens in `src/theme.ts`, lifted from `frontend/src/index.css`).

## 2 · Music structure (analysis/beat_data.json)

100.00 BPM, T = 0.59998 s, grid residual ≤ 14 ms. Video beat *m* = track beat *m*+8, frame = 18 m.

| Video beats | Track | Energy | Use |
|---|---|---|---|
| 0–8 | intro bars 2–3 | low | hook |
| **8** | beat 16, the drop (strongest snare + hat in the window) | slam #1 | colourise |
| 36–40 | bar 11 dip | breath | title card |
| 68–72 | bar 19 dip | breath | "Nothing sends itself." |
| **72** | beat 80, strongest kick re-entry | slam #2 | the Send click |
| **92** | beat 100, bar-25 downbeat | slam #3 | wordmark stamp |
| 96–100 | bar 26, energy falls away | outro hold + fade |

Slams are 64 and 20 beats apart (≥16 ✓). All other beat-locked motion is element-level only.

## 5 · Deliberate deviations

- `deck-deal-flyin` deals 6 cards, not 26 — the run has six segments and inventing extra cards
  would misstate the product. The pile + anticipation + accelerating cadence are kept.
- Light board instead of the card's graphite table (Q7 calls for a dark contrast backdrop on
  object close-ups) — the product's light glass identity wins; contrast comes from depth and shadow.
- The S1 icon field is a metaphor, not a page replica, so it is hand-built (Q1 allows this).
